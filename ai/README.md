# Act 3 — Add AI: Vector Search + In-Database Loan Scoring

> 📺 Part of the [Azure SQL Foundations video series & workshop](../README.md) — companion to <https://aka.ms/azuresqlfoundationseries>.

ZavaFin already migrated their lending database (`ZavaLendingDB`) from on-prem SQL Server
2019 to **Azure SQL Hyperscale** in **Act 1 (Migrate)** — and optionally scaled it for launch
in **Act 2 (Scale)**. The platform is running. Now they want to make it **intelligent** —
without moving data to a separate AI stack or standing up a new platform.

**The overall goal of Act 3:** add AI capabilities to the company's *existing* Hyperscale
database — the one Act 1 migrated. Semantic search over loan narratives and AI loan scoring
run **natively inside Azure SQL**. No data leaves the database boundary, and the DBA keeps
control through familiar SQL Server security primitives.

This is the companion to the Act 3 video — watch along or work straight through at your
own pace.

## Start here — see what you're building

Before touching any SQL, open the internal dashboard and look at the two new AI features
ZavaFin wants to add to it:

1. Open [../application/loan-platform-internal-ai/index.html](../application/loan-platform-internal-ai/index.html) in a browser
   — this is Zava Lending's internal operations console (the same staff app from Act 2).
2. In the left sidebar, find the **AI Intelligence** section and click:
   - **🔍 Narrative Search** — search 12.4 million loan narratives in plain English,
     ranked by semantic similarity (not keyword match).
   - **🤖 AI Loan Scoring** — score a new application against similar historical loans,
     with a risk narrative generated by an LLM.

That "AI Intelligence" section is the target: the AI addition Zava wants layered onto the
internal dashboard they already run on Hyperscale. Everything else in Act 3 is about
building the database features behind those two pages.

## The requirements — what ZavaFin needs

Read [zavafin-ai-sql-needs.md](zavafin-ai-sql-needs.md) for the full scenario. In short,
ZavaFin's underwriters have outgrown full-text search and manual scoring. The five needs:

| # | Requirement | Powers |
|---|-------------|--------|
| 1 | **Semantic search** that understands meaning, not keywords (`FREETEXT` returns 0 rows for the way loan officers actually phrase things) | Narrative Search |
| 2 | **`TOP (N) WITH APPROXIMATE`** — filter by business criteria *during* the DiskANN graph traversal, not after, so underwriters always get *N* usable results | Narrative Search |
| 3 | **Native DML on vector-indexed tables** — new loans are searchable immediately, no index drop-and-rebuild | Both pages |
| 4 | **Faster vector index creation** — the revised vector index builds **6–7× faster** than the original (e.g. the 1M-row benchmark dataset now builds an index in **~2 minutes**) | Index build |
| 5 | **In-database AI scoring** with a cost-effective model (**Phi-4**) via `sp_invoke_external_rest_endpoint` — no data exfiltration, rule-based fallback | AI Loan Scoring |

**Complete [Act 1 (Migrate)](../migrate/) first.** It deploys `ZavaLendingDB` on Azure SQL

## Architecture

AI scoring and writes run on the **primary**. When an Act 2 **Analytics named replica** is
available, the heavy vector reads can be offloaded there for clean workload isolation — but
that's optional, not required to run the demo.

```
  ┌─────────────────────────────────────┐
  │   Internal dashboard / SQL client   │
  │                                     │
  │   ① Query similar loans (replica)   │
  │   ② Get results as JSON             │
  │   ③ Pass JSON to the primary        │
  │   ④ Primary scores + writes decision│
  └──────────┬──────────────┬───────────┘
             │              │
    ┌────────▼────────┐  ┌──▼──────────────────┐
    │ ANALYTICS       │  │ PRIMARY              │
    │ Named Replica   │  │ ZavaLendingDB        │
    │ (optional)      │  │                      │
    │ VECTOR_DISTANCE │  │ sp_invoke_external_  │
    │ + DiskANN index │  │ rest_endpoint → LLM  │
    │ over narratives │  │ → INSERT decision    │
    │ Returns JSON    │  │ → HASHBYTES audit    │
    └─────────────────┘  └──────────────────────┘
```

## Build — deploy the AI capabilities

Run once against the primary to create everything the two capabilities need (prerequisite: a
populated `ZavaLendingDB` from **Act 1**). High level:

1. Add loan narratives + full-text index.
2. Create the embeddings model, embeddings table, and generate embeddings.
3. Build the DiskANN vector index.
4. Create the search procedure (`usp_HybridLoanSearch`) — powers **Narrative Search**.
5. Create the scoring procedure + audit ledger (`usp_ScoreLoanApplication`) — powers **AI Loan Scoring**.
6. *(Optional)* deploy the DAB SQL MCP server + Foundry agent; *(optional)* the APIM gateway.

➡️ **Full run order, prerequisites, and the optional pieces:** [build/README.md](build/README.md)

## Walkthrough — run the two capabilities

With the objects deployed, work through it in two parts:

   scoring end to end.
